# Расширенная привязка лота

Обычная настройка выполняется кнопками. JSON нужен, если поставщик вернул нестандартные поля или мастер не распознал каталог. В меню лота нажмите **Настроить JSON**, вставьте объект, проверьте предпросмотр и сохраните.

Пример для пополнения Steam:

```json
{
  "enabled": true,
  "kind": "steam-topup",
  "product_key": "steam-topup",
  "params": {"amount": 100, "currency": "RUB"},
  "inputs": [{"path": "steamLogin", "label": "Логин Steam (не ник)"}],
  "quantity": 1,
  "max_units": 1,
  "max_cost": "2.50"
}
```

Здесь покупатель получает 100 рублей на Steam. `2.50` — пример порога предварительной закупочной стоимости в USD, а не актуальная котировка. Установите подходящий порог после проверки цены в кабинете поставщика.

| Поле | Значение |
|---|---|
| `enabled` | Разрешена ли обработка новых заказов этой привязки. |
| `kind` | Один из восьми типов API. |
| `product_key` | ID родительского товара; для Steam Top Up и Telegram совпадает с `kind`. |
| `params` | Выбранный номинал, регион и идентификаторы предложения. |
| `inputs` | Какие поля запрашивать у покупателя. Не используйте здесь пароли или коды входа. |
| `quantity` | Количество кодов за одну штуку лота. Для услуг обязательно 1. |
| `max_units` | Максимум штук лота в заказе FunPay. Для услуг обязательно 1. |
| `max_cost` | Порог **предварительной общей** стоимости заказа в USD. Не гарантирует максимальное списание. |

Скопируйте остальные поля из примера и замените `kind`, `product_key`, `params`, `inputs` согласно таблице. Все значения вида `*_ID` — заглушки: нужны реальные значения из текущего `/offers`.

| Вид | `product_key` | `params` | `inputs` (пути) |
|---|---|---|---|
| `giftcards` | `CATEGORY_ID` | `{"category_id":"CATEGORY_ID","card_id":"CARD_ID"}` | `[]` |
| `gamekeys` | `GAME_ID` | `{"game_id":"GAME_ID","key_id":"KEY_ID"}` | `[]` |
| `topups` | `CATEGORY_ID` | `{"category_id":"CATEGORY_ID","offer_id":"OFFER_ID","fields":{}}` | `[{"path":"fields.player_id","label":"ID игрока"}]` — только если API объявляет ключ `player_id`. |
| `steam-topup` | `steam-topup` | `{"amount":100,"currency":"RUB"}` | `[{"path":"steamLogin"}]` |
| `steam-gift` | `APP_ID` | `{"app_id":"APP_ID","sub_id":"SUB_ID","region":"EXACT_REGION_FROM_OFFERS"}` | `[{"path":"invite_url"}]` |
| `telegram-stars` | `telegram-stars` | `{"quantity":50}` | `[{"path":"telegram_username"}]` |
| `telegram-premium` | `telegram-premium` | `{"months":3}` | `[{"path":"telegram_username"}]` |
| `manual` | `SERVICE_ID` | `{"manual_service_id":"SERVICE_ID","product_id":"PRODUCT_ID","fields":{}}` | Поля конкретной услуги из API, например `[{"path":"fields.account_id"}]`. |

У игровых пополнений ключи отличаются. Используйте **точный `key`** из `fields` / `ui.fields` текущего предложения: `player_id`, `account_id`, `zone` и т. д. Не подставляйте название поля вместо ключа. Плагин снимает префикс `fields.` и отправляет объект `params.fields`. Строковые значения сохраняют ведущие нули.

Для списка допустимых значений можно добавить `"choices":["EU","US"]` в объект поля `inputs`. Плагин покажет варианты покупателю и проверит ввод. Не добавляйте поля, которых поставщик не требует. Если обязательные данные нельзя корректно задать, не включайте эту привязку.

Для Steam Gift используйте **конкретные `sub_id` и `region` из одного предложения**. Существование игры в каталоге ещё не означает, что её можно подарить в нужный регион.

Изменение привязки действует на **новые** заказы. Уже принятые заказы хранят снимок настроек, чтобы незаметно не поменять получателя, продукт или количество после оплаты.
